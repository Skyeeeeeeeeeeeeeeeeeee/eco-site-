# Ревью одностраничника «ЭКО СЕРВИС НОВОСИБИРСК»

Дата: 2026-10-04. Объект: `index.html`, `css/styles.css`, `js/content.js`, `js/main.js`, `assets/` (коммит `48ccc6b`).
Как проверял: `python3 -m http.server`, Chromium (Playwright 1.56) на ширинах 360 / 390 / 768 / 1024 / 1100 / 1280 / 1440, плюс 320 и 180 (это 200 % масштаба на 360). Калькулятор сверял с независимой реализацией формулы из `structure.md` §6 на 37 случаях. Контраст считал по WCAG для реально отрисованных пар (текст + итоговый фон с учётом полупрозрачности), в обычном состоянии и в состоянии ошибки. Скриншоты лежат в `scratchpad/pw/shots/review/`.

## Критично

### К1. Сообщения об ошибках в форме первого экрана нечитаемы (контраст 1.69:1)
- **Где:** `css/styles.css:349` — `.on-dark .field[data-state="error"] .field__msg { color: #FFB3C0; }`. Hero-форма (`index.html:206–238`) лежит внутри `section.hero.on-dark`, но сама карточка белая (`.form-card`, `styles.css:218`).
- **Проблема:** правило для тёмного контекста бьёт по белой карточке. Все 4 сообщения («Подскажите, как вас зовут» и остальные) выводятся цветом #FFB3C0 на #FFFFFF. Это 1.69:1 при норме 4.5:1. Это главная форма страницы, и пользователь не видит, что исправить.
- **Как воспроизвести:** 390×844, нажать «Получить расчёт» с пустыми полями. `getComputedStyle(#h-name-msg).color = rgb(255,179,192)`. Скан контраста показывает единственный провал на странице: `#FFB3C0 on #FFFFFF 1.69`, 4 вхождения. Скриншот: `shots/review/hero-errors-390.png`.
- **Исправление:** вернуть внутри карточки обычный цвет ошибки:
  ```css
  .on-dark .form-card .field[data-state="error"] .field__msg { color: var(--c-error); } /* 5.76:1 на paper */
  ```
  Либо сузить исходное правило, например до `.calc-result .field…`, где фон действительно тёмный. Сейчас в тёмных контекстах полей нет вообще.

### К2. Форма «Узнать стоимость доставки» собирает телефон без согласия на обработку ПДн
- **Где:** `index.html:614–626` (`form[data-form="zone"]`): поля `place` и `phone`, чекбокса `agree` нет.
- **Проблема:** в остальных трёх формах согласие обязательно, а здесь телефон отправляется без него. Это нарушает требование брифа «required consent» и 152-ФЗ. При этом микрокопи обещает перезвонить.
- **Как воспроизвести:** заполнить «Бердск» и `9131234567`, нажать кнопку. Показывается успех «Приняли! Назовём цену доставки…», согласие не запрашивалось.
- **Исправление:** добавить такой же блок `.check` с `data-v="consent"`, `required`, `aria-describedby="z-agree-msg"` и `<p id="z-agree-msg" class="field__msg" role="alert">`. Сетку `.zone-form__form` на ≥768 расширить до `grid-template-columns: 1fr 1fr; ` с чекбоксом и кнопкой на отдельной строке.

## Важно

### В1. Ловушка фокуса мобильного меню не держит фокус
- **Где:** `js/main.js:222–228`.
- **Проблема:** `f = [...ссылки меню].concat([burger])`, поэтому `last === burger`. Ветка «Tab на последнем элементе меню» не срабатывает никогда. Tab с «Рассчитать» уходит под полноэкранный оверлей (`#h-name`, `#h-phone`…), а фокус становится невидим, потому что у body стоит `overflow:hidden`.
- **Как воспроизвести:** 390 px, открыть бургер, Tab ×9. Последовательность: `…Контакты | +7 (383)… | Рассчитать | OUTSIDE | OUTSIDE…`. Отдельный тест: фокус на `.menu__foot a:last-child`, затем Tab переводит фокус на `INPUT#h-name`.
- **Исправление:**
  ```js
  var items = $$('a, button', menu).filter(function (x) { return x.offsetParent !== null; });
  var first = items[0], last = items[items.length - 1];
  if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); burger.focus(); }
  else if (!e.shiftKey && document.activeElement === burger) { e.preventDefault(); first.focus(); }
  else if (e.shiftKey && document.activeElement === first) { e.preventDefault(); burger.focus(); }
  else if (e.shiftKey && document.activeElement === burger) { e.preventDefault(); last.focus(); }
  ```
  Дополнительно можно ставить `inert` на `main` и `footer`, пока меню открыто.

### В2. Маска телефона: Backspace удаляет не ту цифру, каретка прыгает в конец, номера 8-800 ввести нельзя
- **Где:** `js/main.js:503` (`phoneDigits`), `512–518` (`attachMask`).
- **Проблема и доказательства** (набор с клавиатуры в `#h-phone`):
  - Backspace сразу после «) » в `+7 (913) 123-45-67` даёт `+7 (913) 123-45-6`. Удалилась последняя цифра, а не «3».
  - Правка в середине: каретка на позиции 7 и Backspace дают `+7 (911) 234-56-7`, каретка перескакивает на 17 (в конец). Набор «0» на позиции 5 тоже сбрасывает каретку в конец (18).
  - `88005553535` и `8005553535` превращаются в `+7 (005) 553-53-5`, и номер помечается как «не похож на российский». Валидатор при этом разрешает первую цифру 8 (`main.js:537`), то есть маска и проверка противоречат друг другу.
  - Работает нормально: `89131234567`, `+79131234567`, `79131234567`, вставка `+7 (913) 123-45-67`, `8 913 123 45 67`, `…доб. 12`, обрезка лишних цифр.
- **Исправление:** считать количество цифр слева от каретки до форматирования и после `maskPhone` ставить каретку после той же по счёту цифры через `setSelectionRange`. При удалении разделителя удалять цифру слева от каретки, а не последнюю. Префикс 7/8 отрезать только при длине 11 цифр (`if (d.length === 11 && /^[78]/.test(d)) d = d.slice(1)`), тогда «800…» и «8» не съедаются.

### В3. Шрифты: CLS 0.14 на десктопе, ≈305 КБ стороннего трафика, блокирующий CSS Google
- **Где:** `index.html:22–24`.
- **Доказательства:**
  - PerformanceObserver на 1280 px показал CLS = **0.1306–0.1434** (норма ≤ 0.1). Источник: смена шрифта на Unbounded в H1. «биотуалетов» переносится на новую строку, `div.form-card` съезжает с y=458 на y=512 (+54 px), `p.hero__lead` с 382 на 436. Если заблокировать fonts.*, сдвигов нет.
  - Вес шрифтов: 7 woff2 общим объёмом **304 912 Б**, крупнейший Unbounded-файл 119 КБ, плюс CSS 2.5 КБ. Весь сайт без шрифтов около 174 КБ без сжатия.
  - `fonts.googleapis.com/css2` — блокирующий стиль с другого домена. Если Google в РФ отвечает медленно или недоступен, рендер ждёт таймаута.
  - Каждый визит передаёт IP пользователя Google. Для российского бизнеса это лишний риск по 152-ФЗ (трансграничная передача).
- **Исправление:** держать шрифты у себя (`/fonts/*.woff2`), только subset `cyrillic` + `latin` (₽ входит в latin-ext, можно добавить один маленький файл). Сделать `<link rel="preload" as="font" crossorigin>` для Unbounded 700 и Onest 400. Добавить fallback с метриками, чтобы убрать сдвиг:
  ```css
  @font-face { font-family: "Unbounded Fallback"; src: local("Arial Black"), local("Arial"); size-adjust: 118%; ascent-override: 90%; }
  --font-display: "Unbounded", "Unbounded Fallback", …;
  ```
  Коэффициенты подобрать в браузере.

### В4. Диапазон 1024–1279: в шапке нет ни навигации, ни телефона, ни «Рассчитать», меню мобильное на всю ширину
- **Где:** `css/styles.css:185–200` (навигация включается только с `min-width:1280px`), `styles.css:638` (sticky-панель скрыта с 1024).
- **Проблема:** design-system §6.16 требует навигацию с 1024. Перенос на 1280 оправдан: при принудительном показе на 1024 строке шапки нужно **1179 px**. Но взамен ничего не сделано. На 1024–1279 в шапке только иконка-телефон и бургер. Номер текстом не виден, sticky-панели уже нет, единственный постоянный CTA — FAB «Заказать звонок». Бургер открывает мобильное меню на весь экран с кнопками шириной 1036 px (`shots/review/menu-1100.png`).
- **Исправление:** на 1024–1279 показывать `.header__phone` (текстом) и `.header__calc`, а навигацию либо сократить (убрать «Как работаем» и «Отзывы», уменьшить `padding` до 6px и шрифт до .875rem), либо оставить бургер, но меню сделать боковой панелью `max-width: 420px` с кнопками `width:auto`.

### В5. FAB «Заказать звонок» перекрывает ссылку в карточке результата калькулятора
- **Где:** `css/styles.css:639` (`.fab { right:24px; bottom:24px }`) и `457` (`.calc-result` sticky).
- **Доказательства:** при 1024×768 в калькуляторе прямоугольник FAB [782,696–1000,744] пересекается с `#res-share` [639,669–958,713]. Скриншот `shots/review/calc-1024.png`: «Отправить расчёт в Telegram» наполовину закрыта. Это нарушает WCAG 2.4.11 (сфокусированный элемент не должен перекрываться).
- **Исправление:** прятать FAB, пока `#calc` в зоне видимости (IntersectionObserver, `fab.hidden = true`), или добавить карточке результата `padding-bottom: 72px` на 1024–1279.

### В6. Мобильный калькулятор: мини-итог и sticky-панель вместе занимают 128 px и перекрываются
- **Где:** `css/styles.css:451` (`.calc-mini { bottom: calc(76px + …) }`) и `634–636` (высота панели фактически **84 px**, потому что `.btn` получает `margin-top:6px`).
- **Доказательства:** на 360×740 `calc-mini` занимает 612–664, `sticky-cta` 656–740. Перекрытие 8 px, вместе 17 % экрана (`shots/review/vp360-calc2.png`). Кнопка «Рассчитать» в панели, пока пользователь уже внутри калькулятора, ничего не делает.
- **Исправление:** пока `#calc` пересекает viewport, скрывать `sticky-cta` (`data-visible="false"`) и ставить `calc-mini` на `bottom: calc(12px + env(safe-area-inset-bottom))`. Как минимум выставить `bottom: calc(84px + 8px + env(...))`.

### В7. Обещание «цена из калькулятора = цена в договоре» противоречит «примерно / ориентир»
- **Где:** `js/content.js:243` (строка сравнения «Цена в договоре и в калькуляторе — Одна и та же»), `index.html:307` («Цена из калькулятора — цена в заявке»). С другой стороны: `index.html:372` («Точную — подтвердим по телефону»), `465` («Примерно»), `486` («Это ориентир…»).
- **Проблема:** клиент попросил не давать конкретных обещаний. Сейчас сайт одновременно гарантирует совпадение цены и называет её ориентиром. Это юридически уязвимо и сбивает с толку.
- **Исправление:** заменить на «Цену фиксируем в договоре до оплаты» и «Итог назовём до оплаты — он не вырастет без вашего согласия». Также отдать клиенту на подтверждение оставшиеся конкретные сроки: «перезвоним за 15 минут» (`index.html:207, 267–269, 669, 777`; `content.js:124–127, 206`), «в день заявки до 14:00» (`content.js:264, 314`), «звоним за 30 минут» (`225, 316`), «КП в течение рабочего дня» (`index.html:331`), «договор за 1 рабочий день» (`content.js:252`), «Ни разу не подвели» (`301`).

### В10. Основной контент существует только после выполнения JS
- **Где:** пустые контейнеры в `index.html`: `#cab-grid` (356), `#steps` (511), `#service-list` (526), `#why` (553), `#vs` (559), `#docs-list` (580), `#zone-list` (609), `#rev-track` (641), `#faq-list` (659), `#contact-list` (673), `#footer-nav` (738). FAQPage JSON-LD создаётся в `main.js:171–177`.
- **Проблема:** H3 моделей с ключевыми запросами («торфяной туалет», «кабина для маломобильных»), цены, FAQ и контакты отсутствуют в исходном HTML. Поисковик без рендера JS (Яндекс рендерит не всегда) и пользователь с отключённым или упавшим JS увидят пустые блоки.
- **Исправление:** не нарушая правило «данные в `content.js`», добавить простой шаг сборки: Node-скрипт из 30 строк, который загружает `content.js` в vm, вызывает те же render-функции и записывает готовый `index.html` (пререндер). Минимальный вариант: зашить в HTML статический FAQPage и каталог, а JS пусть только гидрирует.

### В11. При 200 % масштаба на 360 px появляется горизонтальная прокрутка

При 320 px всё в порядке, то есть формально WCAG 1.4.10 соблюдён, но design-system §9.9 требует 200 % на 360.
- **Исправление:** `@media (max-width: 300px) { .logo__text { display:none } .hero h1 { font-size: 1.25rem; hyphens:auto } .facts { grid-template-columns: 1fr } .form-card { padding: 14px } }`, у H1 `overflow-wrap:anywhere` для «Новосибирске».

- **Исправление:** либо сделать окно немодальным поповером (убрать `role="dialog"`, оставить `aria-expanded` у FAB и `aria-controls`), либо добавить `aria-modal="true"`, ловушку Tab и закрытие по клику снаружи. Проще всего нативный `<dialog>` с `showModal()`.

### В14. На 1024–1279 нет ни одного видимого текстового телефона на первом экране
Связано с В4, но выделено отдельно как риск конверсии: на ноутбуках 1100–1279 px номер виден только в футере и в меню. Для сервиса «позвоните — назовём цену» это заметная потеря. Исправление то же, что в В4: показывать `.header__phone` начиная с 1024.

### Ж1. Калькулятор: пограничные случаи (формула во всех 37 сценариях совпала, см. «Проверено»)

Последствия: текст не двигается вместе с лицом на hover и active, понадобился хак `margin-top:6px` на всех `.btn` (из-за него sticky-панель стала 84 px вместо 76), у disabled «лицо» остаётся (DS: `::before { display:none }`). Визуально почти незаметно, но лучше выровнять с DS.

Нет «выпрыгивания» номеров шагов, вертикального маршрута на мобиле (DS разрешает упрощение), покачивания стикеров и наклона отзывов. Порог reveal 0.12 вместо 0.15. Некритично.

### Ж9. Совместимость: `MediaQueryList.addEventListener` роняет всю инициализацию на старом Safari
`main.js:230`: в Safari < 14 (iOS 13) метода нет. Исключение в `initMenu()` прерывает `init()`, и не запускаются `initTabs`, `initCalc` и формы. Исправление: `var mq = matchMedia(...); (mq.addEventListener ? mq.addEventListener('change', fn) : mq.addListener(fn));`.

### Ж10. Шаблоны `innerHTML` не везде экранируют значения из `content.js` (риск низкий)
Без `esc()` в атрибуты подставляются: `m.calcModel`, `m.need` (`main.js:67–68`), цвета в `style` (70), `m.art.vb` и `m.art.sym` (73), `z.cls` и `z.id` (112), `r.kind` и `r.stars` (138, 141), `g.id` (153), `f.g` (156), `m.id` (337, 339). `esc()` не экранирует `'`. В `bindContacts` (`main.js:24`) можно подставить `javascript:`-URL. Данные свои, поэтому риск низкий, но стоит пропускать всё через `esc()` и проверять схемы `href` (`tel:`, `mailto:`, `https:`).

### Ж11. Мелочи ARIA и семантики
- `article.zone` с `tabindex="0"` и `aria-label` (`main.js:112`) дают три лишние остановки Tab, а `aria-label` подменяет содержимое (условия и цена не озвучиваются в режиме фокуса). Нужно убрать `tabindex` и `aria-label`, подсветку карты делать по hover и по фокусу внутри.
- `aria-current` в навигации не снимается при возврате наверх: на hero остаётся «Вопросы» (`main.js:235–241`, hero не наблюдается).
- `<h3>` внутри `<summary>` (`main.js:156`): VoiceOver и часть читалок теряют роль заголовка у потомков `summary`. Лучше `<summary><span class="faq__q" role="heading" aria-level="3">`.
- `<aside>` используется для клякс (`index.html:267`, `main.js:92`). Это лишние complementary-ориентиры, лучше `div`. `div.blobs aria-label="Цифры"` без роли (`index.html:554`): атрибут игнорируется. `aria-hidden="false"` (`index.html:241`) избыточен.
- В калькуляторе одна ошибка озвучивается дважды: `#n-msg role="alert"` и `#res-sr aria-live`. Внутри калькулятора лучше оставить только debounce-регион `#res-sr`, а у `field__msg` убрать `role="alert"`.

### Ж12. Ссылка «в Telegram» с предзаполненным текстом
`https://t.me/eco_service_nsk?text=…` (`main.js:414`): параметр `text` для ссылок на пользователя поддерживается не во всех клиентах. Нужно проверить на iOS, Android и Desktop. Запасной вариант: `https://t.me/share/url?url=<сайт>&text=…`.

### Ж13. Разметка для SEO
- Нет Product/Offer для каталога (`structure.md` §16 требует).
- В LocalBusiness нет `image`, `geo`, `logo`. `dayOfWeek` лучше указывать как `https://schema.org/Monday`.
- Rich results по FAQPage Google с 2023 года почти не показывает. Разметка не вредит, но ждать от неё многого не стоит. Для Яндекса полезнее статический контент (см. В10).
- `og:image` указывает на несуществующий `assets/og.png` (помечено ЗАГЛУШКА, перед запуском добавить 1200×630).

### Ж14. Сжатие и стоимость JS при старте
- Python-сервер отдаёт файлы без сжатия: HTML, CSS и JS занимают 174 КБ. С gzip было бы около 44.6 КБ (HTML 12.5, CSS 12.2, content 8.2, main 11.8). На проде нужно включить brotli или gzip и `Cache-Control` для `css/` и `js/`.
- Две long task по 104–134 мс при инициализации (desktop без троттлинга). На слабом телефоне это около 0.4–0.5 с TBT. Ниже первого экрана (отзывы, FAQ, зоны, контакты) можно рендерить через `requestIdleCallback`, но при пререндере из В10 проблема уходит сама.

### Ж15. Ссылки-заглушки `href="#"`
«Политика конфиденциальности», «персональных данных» и «Образец договора» указывают на `#`. Клик молча гасится (`main.js:621–623`). Это нормально как заглушка, но ссылка на политику обязательна для законного сбора ПДн: перед запуском заменить `privacyUrl`.

### Ж16. `prev` маски не сбрасывается после «Отправить ещё одну»
`main.js:513`: после `form.reset()` переменная `prev` хранит старый номер. Обычно не мешает, но в редком случае первое удаление сработает как «удаление разделителя». Сбрасывать в `reset`.
